# Clean rebuild plan — 1 November 2026

## Request and status

On 1 November 2026 the user asked for a redesign from first principles, covering architecture and implementation as well as UI/UX: “if you were to rebuild the same thing from scratch, how would you do it?” Feature additions and removals were in scope, following jstack `rule-lean`. The stated reason: “it is clunky, feels unoptimized, large bundle size, and buggy. macos feel stable but the windows build is unusable, and app delivery is bad.”

The proposals were presented in two grill-form rounds: [round 1](2026-11-01-grill-2429f43a2dda41cdf1aaa20116f739b4.md) and [round 2](2026-11-01-grill-8310ced881c9d8f1fe6b9c2f5277b081.md). In round 2 the user authorized starting milestone 1, then asked for a handoff to another agent instead of continuing in the same session. The [implementation handoff](2026-11-01-werk-handoff.md) consolidates these decisions into a specification. The user then asked to resolve its open questions before handing over; [round 3](2026-11-01-grill-28a582f50b30795a161c06d0221e222e.md) and [round 4](2026-11-01-grill-79bc64157692f581ef75d39f3c59308f.md) and [round 5](2026-11-01-grill-9472293cf4bb700313881eac8d7833b7.md) did that. The same session deleted the old app, archived it on `legacy`, and restructured the repository and wiki for werk. The [decision register](../decisions/index.md) is the current list of decisions; the table below is the record of rounds 1 and 2.

## Findings

Measured on 1 November 2026 with read-only queries and file listings.

| Area | Observation |
| --- | --- |
| Package | Installed macOS bundle 698 MB: application with full `node_modules` 310 MB, headless Chromium 198 MB (letter PDFs and legacy resume exports only), Node + Tectonic + sandbox helper 155 MB, TeX cache 20 MB. The Windows package measured 1.0 GB on 18 October, before the Pi change (legacy wiki: Pi runtime handoff). |
| Database | Canonical SQLite database 2.0 GB plus a 188 MB WAL. HTTP response bodies 979 MB, source item versions 380 MB, jobs 352 MB, source items 282 MB. |
| Collection | 45,351 jobs. About half are classified Other and about a sixth Stretch. Opened, saved and applied counts and per-source yield were measured locally and are retained outside the wiki as application records; all saved jobs were Strong or Adjacent. |
| Process model | API and worker run as separate processes coordinated through SQLite leases, a heartbeat and revision triggers. The UI polls every 8 seconds, and filtering rebuilds an in-memory snapshot of every job. |
| Frontend | 3.5 MB built: LaTeX editor chunk 964 KB plus 273 KB CSS, pdf.js worker 1.1 MB, assistant chunk 295 KB, main chunk 548 KB. |
| Windows | User-reported: installation fails or is confusing; blank window or will not start; slow or freezes; crashes or stops in the background. |

## Accepted direction

These decisions apply to the rebuilt app. Unless a row says otherwise, the user accepted the recommendation presented in the form.

| ID | Decision |
| --- | --- |
| REB-audience | Public GitHub release for anyone. Platforms: macOS Apple Silicon and Windows 11 x64. Unraid/Docker and Linux desktop are dropped from the rebuild. |
| REB-runtime | Electron, TypeScript only. The packaging tool replaces the Go/Cocoa/Win32 hosts, PowerShell installer and checksum inventory. Electron 44.9.0 includes `node:sqlite` with FTS5 (verified), so no native module is needed. |
| REB-delivery | Unsigned builds on both platforms; an in-app notice links to a newer GitHub release (a read-only check). This differs from the recommendation to sign. Consequence: Gatekeeper and SmartScreen prompts on first open and no automatic updates, so install instructions must explain both. |
| REB-clean | Start completely clean. Import no profile, CV, jobs or letters. User note: “dont import profile or CV. start completely clean. but keep a backup of my data, and put it on ~/Desktop/ununemploy-backup”. This differs from the recommended ZIP import. |
| REB-process | One backend process owns the API, scheduler and serialized model queue. It pushes changes to the UI and persists queued work in SQLite. |
| REB-retention | Keep Strong and Adjacent jobs unless they are Incompatible. Keep a fingerprint (URL, content hash, profile revision) for everything else, and re-check it on the next sighting after a profile change. Delete unsaved jobs 30 days after they close. No HTTP body cache, and no description history for unsaved jobs; saving still snapshots the description. |
| REB-documents | The CV stays LaTeX with a compiled PDF, as today. Cover letters are plain text only: no PDF, no LaTeX letter template and no Chromium. User correction in round 2: “i want CVs in latex PDF, like today. plain text only for letters.” |
| REB-cv-source | The master CV is generated from the profile on request, then edited by the user or the assistant. Each generation is a new version; manual edits are never overwritten without the user's action. Per-job CVs remain excluded. |
| REB-name | The new app is named **werk**, styled in lowercase. |
| REB-repo | Same repository. The current app is archived on a `legacy` branch, and the wiki restarts for werk. |
| REB-retire | Stop using the current app now; remove it and its data folder. The user confirmed the exact paths in round 3, and they were deleted on 1 November. |
| REB-builds | Release builds run on GitHub Actions when a version tag is pushed, producing unsigned installers in a draft GitHub Release. |
| REB-start | Start implementation with milestone 1: shell, backend process, database foundation, unsigned installers for both platforms and the update notice, proving Windows installation and startup first. |
| REB-stack | Backend bundled with esbuild. Typed columns, SQL indexes and FTS5 search, with JSON only for raw source evidence. TanStack Query invalidated by push events. One module per page. A plain chat UI instead of assistant-ui. Minimal CodeMirror for the LaTeX editor and the built-in Chromium PDF viewer for the CV preview. Ported unit tests plus one Playwright suite against the packaged app on both platforms. Settings → Diagnostics. |
| REB-inbox | The opening screen is a triage inbox. **New** lists unreviewed jobs that pass the search criteria, best match first. Save or Skip removes a job from New, and **All matches** keeps it searchable. Unopened titles are bold. |
| REB-criteria | Profile → Search criteria decides what is collected and what appears in New. Filters only narrow a view temporarily. |
| REB-timezone | Minimum working-hours overlap with the user's timezone, at country level, replacing the UTC range map and rotating offset. |
| REB-detail | A decision summary followed by the description with matched and missing requirements highlighted. No Match tab or metadata grid. |
| REB-saved | A saved job opens a workspace: posting and notes beside the letter, with review notes and status visible. |
| REB-lifecycle | Saved and Applied only, as manual records shown in the job header and list. |
| REB-profile | A fact sheet with status and source for each fact, editable directly or through the assistant. This revises the 8 October read-only viewer; direct edits are attributed to the user with a date. |
| REB-navigation | Inbox, Saved, Profile and CV; Sources moves inside Settings. |
| REB-sources | Keep sources that produced saves, Greenhouse/Ashby/Lever company boards, structured feeds and APIs, and scraped public boards. Drop Hacker News (Who's Hiring and YC jobs), X search, and the configured boards that never returned a job: Indeed, Careerjet, Jooble, Adzuna, Tech in Asia, Welcome to the Jungle, NodeFlair, Tech Jobs for Good, Foorilla and Web3.career. Keeping scraped boards differs from the recommendation. |
| REB-additions | Keyboard triage, a first-run setup checklist, and Hide company. Not selected: Track company, status counts, recording versions when applying, saved views. |
| REB-removals | Seen state and filter, the duplicate grouping control, legacy resume code, retired Jev code, the HTTP body cache, description history for unsaved jobs, VueJobs detail enrichment, and the custom installer and checksum inventory. |

Unchanged: no application submission, uploads, form filling, outreach or engagement; pi-ai with the ChatGPT subscription, `gpt-5.6-sol` and high reasoning; a cover letter generated on save; the right-hand assistant overlay; local data with no login; deterministic matching and eligibility evidence rules; the Cursor/Clarity visual language. ZIP backups remain an existing requirement for the new app's own data unless changed.

## Effect on current requirements

`AGENTS.md` was replaced with the werk version, the wiki restarted, and the previous app was archived on the `legacy` branch. Superseded: the Unraid target, the Go/WKWebView hosts, the read-only profile viewer, the browse-everything inbox, Seen, cover-letter PDFs and the ununemploy name. Unchanged boundaries carry over verbatim.

## Data backup

On 1 November the user's data was copied to `~/Desktop/ununemploy-backup`, which is local only and contains credentials. It holds the installed app's appdata, the checkout's ignored evidence files and `.env`, and the older `.local-data`. Both databases were copied with SQLite's backup API; `PRAGMA quick_check` returned ok and selected table row counts matched the originals. A README in the folder lists the contents. Before `.local-data` was deleted, the private grill-form records were moved into the backup's `grill/` folder.
