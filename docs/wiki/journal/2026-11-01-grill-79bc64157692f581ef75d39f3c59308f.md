## Question 46

```text
Round: CV compiler isolation
Question: How should werk isolate CV compilation?
Description (Markdown source):
You asked what would be better than the Go helper if we started from scratch. I tested Tectonic 0.15.0 (the compiler werk will use) without a sandbox, with all of its security options on (`--untrusted`, cached packages only). A crafted CV source could still:

- **read any file you can**, by absolute path or `../`, including through obfuscated macros, images and embedded PDFs;
- **write any file you can** the same way. That is enough to plant a script that runs at login.

Tectonic records each file it reads and writes, but only after the write has happened, so checking afterwards is not safe. Last round's fallback, rejecting file commands in the source, would not stop this either. A boundary in the operating system or in the engine is required.

| Approach | Status |
| --- | --- |
| OS sandbox: the built-in `sandbox-exec` on macOS, an AppContainer helper on Windows | Verified for the legacy app on both platforms (Windows checks passed on 17 October). The helper is about 230 lines of Go, built in CI. |
| TeX compiled to WebAssembly with an in-memory file system | No file access at all, by construction. Identical on both platforms, with no helper. But every candidate is unsuitable today: busytex (MIT) is TeX Live 2023, browser-only and has no published releases; its TeX Live 2026 fork, TeXlyre BusyTeX, and SwiftLaTeX (last updated 2024) are AGPL-3.0, which conflicts with MIT. |
| A werk build of Tectonic that refuses paths outside its work folder | The same compiler on both platforms without an OS sandbox, but werk would build and maintain its own Tectonic: a large Rust and C build in CI. |
| Calling AppContainer from TypeScript through a native FFI library | Removes Go, but adds a native module and rewrites code that is already verified. |
Recommendation: The OS sandbox, reusing the verified helper. It is the only option that is both proven and maintainable today. WebAssembly is the better design once a maintained, permissively licensed TeX build exists; the handoff notes that as a later replacement.
Selection: single
Options: OS sandbox: sandbox-exec on macOS, the Go AppContainer helper on Windows / Try busytex WebAssembly in milestone 4; fall back to the OS sandbox if it fails / A werk build of Tectonic that refuses outside paths
Selected: OS sandbox: sandbox-exec on macOS, the Go AppContainer helper on Windows
Notes: why do we need an isolated sandbox for cv compilation?
```
