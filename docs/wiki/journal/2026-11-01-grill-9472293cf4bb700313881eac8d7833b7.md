## Question 47

```text
Round: CV compiler isolation, rule-lean
Question: Should werk remove the need for a CV sandbox instead of building one?
Description (Markdown source):
**Why a sandbox at all.** LaTeX is a programming language that can read and write files. In the current plan, the assistant edits your CV's LaTeX, and it also reads job postings, which anyone can write. A posting with hidden instructions could get the assistant to add a line that copies a private file, such as your ChatGPT sign-in token, into your CV PDF. You would then send that PDF to the employer who wrote the posting. My test showed that Tectonic does this even with its safety options on, and can also write files anywhere, such as a script that runs at login. The sandbox blocks both.

**The rule-lean alternative removes the cause.** Untrusted text never becomes LaTeX. The model writes CV content as plain fields, and werk's template escapes them into LaTeX, so they can only ever print as text. Only you type LaTeX. To change the CV, the assistant edits facts in your profile or regenerates the CV with your instructions (for example “one page, lead with backend work”). Each regeneration is a new version, and your manual edits stay in earlier versions.

| | Keep the sandbox | Untrusted text never becomes LaTeX |
| --- | --- | --- |
| Assistant and the CV | Edits the LaTeX directly | Regenerates with your instructions; edits profile facts |
| Code to build and keep working | macOS sandbox profile; 230-line Go helper for Windows; Go in CI; AppContainer setup (private copies of the compiler and packages, redirected folders, a font configuration) | One escaping function with tests |
| Windows risk | The most platform-specific part of werk | Nothing added |
| LaTeX you paste from elsewhere | Compiled inside the sandbox | Runs with your permissions, as in any local TeX setup |
Recommendation: Remove the cause. It closes the same hole with far less code, drops werk's only non-TypeScript component and its most Windows-specific setup, and keeps the assistant useful for the CV through regeneration.
Selection: single
Options: No sandbox: untrusted text never becomes LaTeX; the assistant regenerates instead of editing LaTeX / Keep the OS sandbox; the assistant edits LaTeX directly
Selected: Keep the OS sandbox; the assistant edits LaTeX directly

```
